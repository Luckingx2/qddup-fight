# 큐떱대전

캐릭터 15명 중 한 명을 골라 CPU와 싸우는 1인용 대전 게임입니다. 상대와 스테이지는 주사위처럼 돌다가 랜덤으로 정해지고, 3판 2선승입니다.

빌드가 필요 없는 정적 사이트입니다. `index.html`과 `assets/` 폴더를 그대로 올리면 동작합니다.

## 캐릭터와 필살기

| W2 | 저음 지진: 땅에 있는 상대만 맞고 잠깐 기절한다 | E2 |

- 태그기는 태그 버튼으로 발동합니다. 게이지 100%가 필요하고 라운드당 1회입니다.
- 필살기·태그기는 영상이 먼저 재생되고, 공격 버튼이나 화면 탭으로 건너뜁니다.
- 스테이지 13개: 애니세상, 체육관, 도넛가게, 밴드연습장, 콘서트 무대, 옥상, 해변, 놀이공원, 눈마을, 우주정거장, 아쿠아리움, 한옥 야시장, 지하실

## 온라인 대전

캐릭터 선택 화면 아래의 `온라인 방 만들기`를 누르면 6자리 방 코드가 뜹니다. 상대는 `방 참가`에 코드를 넣거나 초대 링크(`?room=코드`)로 들어옵니다. 둘 다 캐릭터를 고르고 준비를 누르면 시작합니다.

- 두 기기가 직접 연결(WebRTC)되고, 접속 중개는 무료 공용 PeerJS 서버를 씁니다. 별도 서버나 가입이 필요 없습니다.
- 방을 만든 쪽 기기가 게임을 계산하고 상대는 화면을 받아 봅니다. 참가한 쪽은 회선 상태만큼 입력이 늦게 반영됩니다.
- 온라인에서는 필살기 영상을 건너뛸 수 없습니다.
- `assets/peerjs.min.js`가 접속 라이브러리입니다. 지우면 온라인 대전이 동작하지 않습니다.

## 파일

| 경로 | 내용 |
|---|---|
| `index.html` | 게임 전체(화면, 로직, 효과음 합성) |
| `assets/<키>.webp` | 캐릭터 동작 스프라이트 15개 |
| `assets/<키>_face.webp` | 캐릭터 얼굴 15개 |
| `assets/bg_*.jpg` `th_*.jpg` | 스테이지 배경 13종과 미리보기 |
| `assets/sp_<키>.mp4` | 필살기 영상. 뒤에 `2`가 붙으면 두 번째 필살기, `T`가 붙으면 태그기 |
| `assets/title.jpg` | 첫 화면 타이틀 그림 |
| `assets/peerjs.min.js` | 온라인 대전용 접속 라이브러리 |
| `.nojekyll` | GitHub Pages가 파일을 그대로 서빙하게 하는 빈 파일 |

파일 키: Q, W, E, R, G(EGG), B(BING), Qb(Q2), Wb(W2), Eb(E2), Rb(R2), Qc(Q3), Wc(W3), Ec(E3), Rd(R3), Rc(R4).
태그 영상은 한 쌍이 하나를 같이 씁니다: `sp_GT`(EGG·BING), `sp_QbT`(Q2·R2), `sp_WbT`(W2·E2), `sp_QcT`(Q3·R3), `sp_WcT`(W3·E3), `sp_RcT`(R4).
영상 파일이 없는 기술은 영상 없이 짧은 정지 연출 후 바로 발동합니다.

## 배경음악

`assets/bgm.mp3`가 있으면 그 곡을 반복 재생하고, 없으면 스테이지별 합성 음악이 나옵니다. 이 묶음에는 `bgm.mp3`가 없습니다. 구매한 음원은 공개 저장소에 올리지 마세요.

## 아이폰 Safari 확대 문제

공격 버튼을 빠르게 두 번 누르면 화면이 확대되던 문제를 막아 두었습니다. 이 처리는 `index.html` 안에 있으므로 배포 쪽에서 따로 덧붙일 필요가 없습니다.

## GitHub Pages 배포

1. 저장소 루트에 이 폴더의 모든 파일을 올린다(`.nojekyll` 포함).
2. Settings → Pages → Source `Deploy from a branch`, Branch `main` / `/ (root)`.
3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/`에서 연다.

## 조작

- 폰: 왼쪽 패드(좌우 이동, 위 점프, 아래 가드), P 펀치, K 킥, 필살, 태그
- PC: 방향키 + Z·X·C·V, 또는 WASD + J·K·L·;

## 빠른 대전과 누적 랭킹

타이틀 화면에서 2~16자 닉네임을 입력합니다. 빠른 대전은 일반 대기열을 사용하고, 랭킹전은 점수가 비슷한 상대를 먼저 찾습니다. 랭킹 점수는 1,000점에서 시작하며 승리하면 25점, 패배하면 15점을 잃습니다. 순위표에는 랭킹전 기록이 있는 상위 50명이 표시됩니다.

로그인 없이 플레이하며 브라우저에 저장된 무작위 키가 랭킹 기록을 식별합니다. 닉네임은 표시용이라 같은 닉네임을 입력해도 다른 기기의 기록에 접근할 수 없습니다. 브라우저 데이터를 지우면 그 기록을 다시 연결할 수 없습니다.

기존 PeerJS 대전을 사용합니다. 랭킹전은 두 브라우저가 동일한 승자를 보고하면 한 번만 점수를 반영합니다. 경기 시뮬레이션은 방장 브라우저에서 실행되므로 서버 판정 및 조작 방지 기능은 제공하지 않습니다. 연결이 끊겨 양쪽 결과가 도착하지 않은 경기는 점수를 반영하지 않습니다.

### Cloudflare Worker 배포

Cloudflare 계정에서 D1 데이터베이스를 만들고 `online/wrangler.jsonc`의 `database_id`에 연결합니다. Worker와 D1 마이그레이션을 배포한 뒤, `index.html`의 `online-api` 메타 태그에 Worker의 HTTPS 주소를 넣습니다. GitHub Pages의 정적 게임은 이 API에 매칭과 랭킹만 요청합니다.

```sh
cd online
npx wrangler d1 create qddup-fight
npx wrangler d1 migrations apply DB --remote
npx wrangler deploy
```

로컬에서 연동할 때는 `--local`로 마이그레이션을 적용하고, `wrangler dev --var GAME_ORIGIN:http://localhost:8000`으로 실행합니다. 게임은 별도 HTTP 서버에서 `http://localhost:8000`으로 열고 `online-api`를 로컬 Worker 주소로 지정합니다.
